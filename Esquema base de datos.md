# Esquema base de datos

Documento generado a partir de las migraciones Flyway en `src/main/resources/db/migration` y las entidades JPA en `src/main/java/co/edu/icesi/pdg/mte`.

## Convenciones generales

- Motor objetivo: PostgreSQL/Supabase, con soporte de H2 en pruebas.
- ORM: Spring Data JPA / Hibernate.
- Migración base: `V1__initial_schema.sql`.
- Migración correctiva aplicada: `V4__alter_objective_quarter_to_integer.sql`.
- Llaves primarias simples: `BIGINT GENERATED BY DEFAULT AS IDENTITY`, salvo tablas puente con llave compuesta.
- Campos enum: almacenados como `VARCHAR` por `@Enumerated(EnumType.STRING)`.
- Fechas:
  - `DATE` para fechas calendario.
  - `TIMESTAMP WITH TIME ZONE` para instantes de creación, actualización o sincronización.
- Números:
  - `NUMERIC(12,2)` para valores cuantitativos amplios.
  - `NUMERIC(10,2)` para porcentajes calculados.
  - `NUMERIC(5,2)` para pesos y porcentajes acotados.

## Reglas de negocio visibles en el modelo

- Un objetivo siempre pertenece a una meta institucional, una apuesta estratégica, un departamento y un periodo académico.
- `objective.quarter` solo acepta valores entre `1` y `4`.
- Un resultado clave siempre pertenece a un objetivo y a una unidad de medida; el periodo académico es opcional.
- El progreso de un resultado clave se puede calcular desde enlaces activos a proyectos finalizados, sumando `project_key_result_link.contribution_weight`.
- Un proyecto siempre apunta a un resultado clave principal por `project.key_result_id`.
- Además del resultado clave principal del proyecto, la tabla `project_key_result_link` permite vínculos adicionales o trazabilidad con proyectos externos.
- `project_tutor` no modela tutores como profesores; guarda nombres en texto libre.
- `audit_log` no usa FK directa para la entidad auditada; maneja referencia lógica por tipo e identificador.
- Hay una diferencia menor entre migración y JPA en `project.created_at`: la migración permite nulo, pero la entidad JPA lo declara no nulo y lo inicializa con `Instant.now()`.
